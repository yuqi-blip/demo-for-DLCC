## Notation

- `NN_pred` / `u_pred`: solution network `NN_1`; weights `solution_network*.pth`.
- `NN_ing*`: auxiliary networks; weights `integral_network*.pth`.
- `common/training.py`: consistency and PIDE losses.
- `reference/`: exact solution and Gauss–Legendre integral.

## Environment

Python 3.11.15, `torch` 2.13.0+cu126, `numpy` 2.4.4, `scipy` 1.17.1, `matplotlib` 3.11.0, `tqdm` 4.68.4. CUDA is used when available, otherwise CPU.

## Data

No external data. 
Reference solutions are generated by `reference/generate_*.py` using the Gil–Pelaez 
inversion formula and Gauss–Legendre quadrature. Generated `.npy` files and trained `.pth` weights allow tables 
and figures to be reproduced without retraining.

### Running from a terminal (not from an IDE)

Every script is launched from **inside its own experiment directory**, and the **model root**
(`Merton_model/` or `Kou_model/`) must be on `PYTHONPATH`, because the scripts import `common.*`
and `reference.*` from the model root while writing their `.pth` / `.png` outputs with relative paths.

The IDE (PyCharm) marks `Merton_model/` and `Kou_model/` as source roots, so plain
`python train_dlcc.py` works there. From a terminal, set `PYTHONPATH` first:

PowerShell:

```powershell
cd DLCC\Merton_model\base_case
$env:PYTHONPATH = ".."          # model root; use "..\.." if you cd deeper
python solution_error.py
```

bash / cmd:

```bash
cd DLCC/Merton_model/base_case
PYTHONPATH=.. python solution_error.py
```

Without `PYTHONPATH` you will get `ModuleNotFoundError: No module named 'reference'`
(or `... 'common'`). The `reference/generate_*.py` scripts need the same setting.

## Weights are portable across CPU and GPU

The shipped `.pth` files were saved from CUDA tensors, so every checkpoint is loaded with
`torch.load(..., map_location='cpu')`. On a CPU-only machine the weights now load correctly and
training/inference still moves the models to CUDA automatically when a GPU is available
(see `common/training.py`). Loading them without `map_location` on a CPU-only machine raises
`RuntimeError: Attempting to deserialize object on a CUDA device ...`.

## Environment hardware

The reported results were produced on a single NVIDIA GeForce RTX 4060 Laptop GPU (8 GB) with
CUDA 12.6. All networks were trained in single precision (`float32`) for 30,000 iterations per
configuration (approximately 8–12 minutes per run on this device); the reference solutions in
`reference/` are computed in double precision.
